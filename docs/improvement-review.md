# 真实案例与多角度改进分析

本轮在现有 MoonVision 上完善数值边界、Node 调用与真实照片预处理流程。保持 MoonBit 公共接口、Replay v1/v2 和已有随机流，不增加训练框架或图像编解码器到核心库。

## 可运行案例：视觉数据预处理

```text
python -m pip install Pillow==12.3.0
python tools/build_web.py
python examples/real_pipeline.py
```

默认使用仓库的 `astronaut_portrait`、`chelsea`、`coffee`，分别覆盖竖幅人物、非方形动物和物体照片。文件与解码像素均按 `web/samples/manifest.json` 的 SHA-256 核验，无需联网。来源归属沿用 [已有记录](../web/samples/ATTRIBUTION.md)。框和关键点明确标为几何探针，只验证标注随像素变换的正确性，不代表人工标注质量或识别准确率。

流程先把图像与探针一起 Letterbox 到 96×96，再进行由固定 seed/sample ID 决定的翻转。随后将输入顺序反转，按 ID 匹配落盘可用的 Replay，检查每张图片及标注与初次结果一致；将结果打包为归一化 NCHW 张量，逐值用独立公式核对通道顺序、batch 步长和均值/标准差，再反归一化确认字节往返。

输出在 `artifacts/real-pipeline/`：

| 文件 | 用途 |
| --- | --- |
| `model-input.json` | 模型前处理可消费的 NCHW 张量；消费方应核对 shape、mean/std 与自身训练约定 |
| `replays.json` | 变换记录与样本 ID、源图哈希、流水线和随机种子；便于溯源与复现 |
| `report.json` | 检查状态、样本 ID、清单哈希与核验结果；失败不能视为验收通过 |
| `preprocessing.png` | 人工检查图像内容与几何标注的前后变化 |

`python examples/real_pipeline.py --help` 列出样本和输出目录选项。示例只接收清单中的 RGB 样本，保持批次通道一致；核心库支持的灰度/RGBA 路径由既有真实图测试覆盖。接入自己的数据时，可复用 Node 案例和 `tools/moonvision_client.mjs`，由应用解码图像并提供同一请求结构；必须保留真实数据来源及标注规则。

Replay 核心只核验尺寸、通道和操作，不验证源图身份。记录中的哈希由本案例校验并保存；外部应用重放时也必须核验自己的输入，不能仅依赖相同 sample ID。JSON tensor 的上限为 262144 个值，96×96 RGB 一次最多容纳 9 张；更大数据集应分批，并保持稳定 sample ID。

## 改进依据与取舍

| 角度 | 发现与影响 | 本轮处理 | 后续验收方向 |
| --- | --- | --- | --- |
| 数值正确性 | 双线性梯度在某邻居权重为零时仍计算其差值；极值像素可触发 `Infinity × 0`，拒绝原本有限的梯度 | 跳过零权重邻居差值，覆盖横纵轴边界，并继续拒绝真正非有限的结果 | 对新采样模式继续同时使用独立参考与有限差分，非光滑点单独定义约定 |
| 输入与故障恢复 | CLI 原先在核心长度检查前把整个文件/行读入内存，缺文件直接出现堆栈 | 增量限长、结构化错误、超限行恢复、输出背压与子进程回归 | 面向服务部署时增加调用超时、并发限制和进程隔离；文本长度预算不能替代所有 CPU/内存预算 |
| 可复用性 | 外部应用只能直接引用编译产物或启动 CLI，调用边界分散 | 提供异步 `invoke`/`processJson`，集中模式、请求和加载错误处理；导入无 CLI 副作用 | 如需公开发布 JS 包，再明确包结构、类型声明、构建产物和版本兼容策略 |
| 真实业务流程 | 真实照片回归完整，但用户需要从文件到训练张量的可执行串联 | 新增来源核验、批次预处理、重放、张量输出、反归一化及预览 | 使用任务自己的人工标注和模型开展端到端评估；本例不宣称训练收益 |
| 复现与兼容 | Replay 不携带照片身份；文档曾将固定取模采样称为严格均匀 | 案例保存 ID/哈希/seed；修正文档措辞，不改变旧随机流 | 若引入无偏采样或新坐标约定，应版本化并提供旧记录兼容测试 |
| 可维护性与交付 | 数值检查无法覆盖文件失败、管道分块、多字节字符或慢消费者 | 新增有针对性的 CLI 回归，案例接入验证入口与 CI，保留已有独立 oracle | 测试断言可观察行为，避免实现细节快照；发布时另外审核打包清单 |
| 性能与扩展 | JSON 文本和数组副本适合可检查的小批次，不能据此保证大规模训练吞吐 | 本轮保持明确预算与小批次示例，避免缺乏数据的架构重写 | 先记录 decode/transport/core 的独立耗时、峰值内存、批次大小，再决定是否增加二进制传输或工作池 |

优先顺序是先保证有限数值、输入边界和复现正确，再根据真实消费者补充部署与吞吐能力。GPU、透视变换、通用模型训练等能力应由具体任务和可验证指标驱动，不在本轮扩大核心 API。

## 验证

```text
python tools/verify.py --references --real-images
```

这会运行四个后端、示例、JSON 桥接、CLI 边界、三套独立参考、Tensor/Grid 封装负向编译、真实预处理案例及 100 组退化图像回归。实际本机结果记录在 [验证记录](validation.md)，运行产物写入被 Git 忽略的 `artifacts/`。CI 配置接入检查不等于远程已经执行通过。
